CORS / fetch prototype

Confirms whether the guest-management app's Apps Script backend can be called cross-origin from this site, before rebuilding the real app around it.

1. Plain GET Not run

A simple GET never triggers a CORS preflight — this should always work if the URL is reachable at all.

—
2. POST as text/plain (the workaround) Not run

JSON body sent with Content-Type: text/plain to dodge preflight, parsed as JSON on the server. This is the pattern the real migration would rely on for saveGuest/deleteGuest.

—
3. POST as application/json (expected to fail) Not run

Deliberately triggers a CORS preflight, which Apps Script web apps typically can't satisfy. Included so you can see the actual failure this migration needs to work around.
